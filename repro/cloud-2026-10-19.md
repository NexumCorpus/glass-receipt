# Cloud stranger repro, 2026-10-19: PASS (with README gaps)

A one-pass run on a clean cloud VM, following the public README as a stranger would. I changed no source file.
This report is the only file added.

**Verdict: PASS.** Every output the README promises came out line for line, with the stated exit codes, on
Python 3.8.20, 3.9.25 and 3.13.16. A wrong root is rejected from the repo root. I recomputed ROOT myself with
`sha256sum` and it matches the published root. The "6 of 6" tally matches the trial files. One trap is real but the
README never claims the opposite: inside the bundle folder, `--root` is silently ignored (gap 1).

## Independent root recomputation

Reading `verify.py`, ROOT is `sha256(bytes of MANIFEST.sha256)`. Each manifest line is `<sha256 hex>  <relative path>`.
Integrity also requires that every file in the bundle (other than the manifest and `__pycache__`) is listed.

```
$ cd bundle-protoprimer-143
$ sha256sum MANIFEST.sha256
209eab8facfd85798cd08f557224e48a55bf3ba76982f814568b1c0a49658be2  MANIFEST.sha256
$ sha256sum -c --quiet MANIFEST.sha256 && echo OK          # all 57 entries
OK
$ diff <(awk '{print $2}' MANIFEST.sha256 | sort) <(find . -type f ! -name MANIFEST.sha256 | sed 's|^\./||' | sort)
(no output: the file set equals the manifest set)
$ git show HEAD:bundle-protoprimer-143/MANIFEST.sha256 | sha256sum
209eab8facfd85798cd08f557224e48a55bf3ba76982f814568b1c0a49658be2  -
```

The recomputed root equals the published root, both from the working tree and from the git blob. 58 files are in the
bundle (57 listed plus the manifest), which matches TRIAL-3's "all 58 files".

## README gaps (numbered)

1. **`--root` is silently ignored inside the bundle folder.** The README's first instruction is to `cd bundle-protoprimer-143`.
   The bundle's own `verify.py` predates `--root`, so if a stranger then adds `--root` with a wrong value, they get
   `VERDICT: VERIFIED` and exit 0 (command 6). The README says to use `--root` "from the repo root" and never claims it
   works in the bundle, so no stated claim is broken. It is the exact hurried-stranger trap TRIAL-2 describes, and a
   README sentence would close it. (TRIAL-2 explains why the bundle copy was left unchanged: re-rooting would break the
   published anchor.)
2. **The two `verify.py` copies differ, and the README does not say so.** The root copy has `--root`, `--bundle` and
   repo-root mode. The bundle copy prints plain `VERDICT: VERIFIED`, without "(root not checked)". The README's
   sentence "Without `--root` it says `VERIFIED (root not checked)`" is true only from the repo root.
3. **"Expected output ends with" lists 3 lines, but they are not the last 3.** `ROW: PASS` is printed between REPLAY and
   ROOT. The listed lines are a subsequence of the output.
4. **The from-root outputs are shown only in prose.** The `== bundle-protoprimer-143` header and the `ROOT CHECK: PASS (…)`
   line are not shown. The "root not checked" verdict has a suffix (`: pass --root <published hex>`) that the README
   leaves out.
5. **Timing is conservative.** The README says "about one second", and selftest "under a second" (its docstring says "a few
   seconds"). Measured: verify 0.04 to 0.14 s, selftest 0.21 to 0.26 s. Not a gap in substance, just slightly
   inconsistent wording between README and docstring.
6. **`--root` is case-insensitive** (an uppercase hex root passes). This is harmless, but undocumented.
